## 每类场景需要准备什么

| 场景 | 适合准备什么 | 更推荐的路线 |
| --- | --- | --- |
| 故事地图 | 主题主线、章节结构、关键地点 | [故事地图路线](/ai/dev/docs/story-builder/) |
| 点位专题 | 点位名称、经纬度、分类、说明字段 | [数据驱动路线](/ai/dev/docs/data-builder/) |
| 路线专题 | 起终点、路线节点、图文说明 | 先故事，再补数据 |
| 行政区划专题 | 边界数据、区域字段、表达目标 | [数据驱动路线](/ai/dev/docs/data-builder/) |
| 灾害/历史专题 | 时间线、地点、图片、说明文案 | 先故事，再视情况补数据 |
| 已有第一版 | 明确哪些部分要改、哪些不要动 | [修改与质量保障](/ai/dev/docs/quality/) |

<Aside type="tip" title="对甲方更友好的表达方式">
讲场景时不要只说“系统能生成地图”。更容易理解的说法是：选择一个相似案例，带着示例需求进入工作区，再把主题、数据和风格替换成当前项目需要的内容。
</Aside>

## 场景页里最值得补的内容

1. 每个场景先判断是故事路线还是数据路线。
2. 每个场景都准备一条可直接复用的需求描述。
3. 对需要数据的场景，先准备最低数据要求，再逐步扩展字段。
4. 对可分享展示的场景，最后补标题、描述和公开方式。
